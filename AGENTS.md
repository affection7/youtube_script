# Правила работы с проектом

## Язык ответов

- Все ответы, сводки, сообщения о завершении задач и описания изменений — только на русском языке.
- Никогда не отвечать на китайском или любом другом языке, независимо от языка кода или комментариев в нём.

## Назначение проекта

Проект — Python-приложение для анализа YouTube-каналов, выявления способов монетизации и генерации персонализированных Cold Outreach сообщений с помощью DeepSeek.

## Стек

- Python.
- Tkinter/ttk для графического интерфейса.
- YouTube Data API v3 через `google-api-python-client`.
- DeepSeek API в OpenAI-совместимом формате через стандартные `urllib` и `json`.
- `unittest` и `unittest.mock` для тестов.
- Скрипты запуска GUI: `start_gui.bat` для Windows и `start_gui.sh` для Linux/macOS.

## Структура проекта

- `agent.py` — ReAct-агент, системный промпт, схема инструментов, цикл вызовов DeepSeek и CLI-запуск.
- `tools.py` — работа с YouTube API, разбор входных данных, анализ матрицы монетизации и сохранение отчетов.
- `app_gui.py` — Tkinter GUI, фоновые потоки и отображение результатов.
- `test_agent.py` — тесты инструментов и основного цикла агента.
- `requirements.txt` — зависимости Python.
- `README.md` — документация по установке и запуску.
- `start_gui.bat` — запуск GUI через `pythonw` в Windows.
- `start_gui.sh` — запуск GUI через `python3` в Linux/macOS, с активацией `venv` при наличии.
- `reports/` — генерируемые отчеты; директория исключена из Git.
- `__pycache__/` — кэш Python; директория исключена из Git.
- `api_key.local.txt`, `deepseek_key.local.txt`, `nordrouter_key.local.txt` — локальные файлы ключей, исключенные из Git.

## Запуск и тесты

Установка зависимостей:

```powershell
pip install -r requirements.txt
```

GUI:

```powershell
python app_gui.py
```

или двойным кликом по `start_gui.bat`.

CLI требует переменные окружения `YOUTUBE_API_KEY` и `DEEPSEEK_API_KEY`:

```powershell
set YOUTUBE_API_KEY=your_google_youtube_key
set DEEPSEEK_API_KEY=your_deepseek_key
python agent.py @handle_or_url
```

Тесты:

```powershell
python test_agent.py
```

Также тесты можно запускать через:

```powershell
python -m unittest -v
```

## Проверки

- После каждого изменения кода запускать `python -m unittest -v`.
- После каждого изменения кода запускать `python -m compileall -q .`.
- Если проверка не проходит, исправить ошибки самостоятельно и не сообщать о завершении задачи, пока обе проверки не пройдены.

## Соглашения по стилю

- Используется стандартный Python-стиль с 4 пробелами.
- В коде применяются type hints и `from __future__ import annotations`.
- Имена функций и переменных — `snake_case`, классов — `PascalCase`, констант — `UPPER_SNAKE_CASE`.
- Публичные функции и основные модули имеют docstring.
- Для JSON используется UTF-8 и `ensure_ascii=False`, чтобы сохранять кириллицу.
- Файлы отчетов создаются в `reports/channels/YYYY-MM-DD/`.
- Секреты нельзя выводить в сообщения, коммитить или добавлять в обычные файлы проекта.
- Ключи могут находиться в переменных окружения, `.env` или `*.local.txt`; агент не читает и не выводит содержимое этих файлов.

## Правила работы

- На задачу нужен один план и одно одобрение; после одобрения выполнить все шаги до конца без дополнительных остановок.
- Спрашивать владельца только при изменении архитектуры, добавлении зависимости, удалении данных или противоречии требований. В остальных случаях принимать решение самостоятельно и записывать его в `PLAN.md`.
- Не останавливаться ради вопроса «продолжать?»: завершить задачу и показать итог.
- Не менять архитектуру, структуру папок и зависимости без отдельного согласования с владельцем.
- После каждого завершённого шага перечисли изменённые файлы и кратко объясни, что и зачем изменено.
- В конце каждой задачи или по просьбе владельца обновляй `PLAN.md`.
- В начале новой сессии сначала прочитай `AGENTS.md` и `PLAN.md`, затем кратко перескажи владельцу, на чем остановились, прежде чем что-либо делать.
- Не читать и не выводить содержимое `.env` и файлов `*.local.txt`; это также ограничено проектным конфигом OpenCode.

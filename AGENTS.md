# Правила работы с проектом

## Назначение проекта

Проект — Python-приложение для анализа YouTube-каналов, выявления способов монетизации и генерации персонализированных Cold Outreach сообщений с помощью DeepSeek.

## Стек

- Python.
- Tkinter/ttk для графического интерфейса.
- YouTube Data API v3 через `google-api-python-client`.
- DeepSeek API в OpenAI-совместимом формате через стандартные `urllib` и `json`.
- `unittest` и `unittest.mock` для тестов.
- Скрипты запуска GUI: `start_gui.bat` для Windows и `start_gui.sh` для Linux/macOS.

## Структура проекта

- `agent.py` — ReAct-агент, системный промпт, схема инструментов, цикл вызовов DeepSeek и CLI-запуск.
- `tools.py` — работа с YouTube API, разбор входных данных, анализ матрицы монетизации и сохранение отчетов.
- `app_gui.py` — Tkinter GUI, фоновые потоки и отображение результатов.
- `test_agent.py` — тесты инструментов и основного цикла агента.
- `requirements.txt` — зависимости Python.
- `README.md` — документация по установке и запуску.
- `start_gui.bat` — запуск GUI через `pythonw` в Windows.
- `start_gui.sh` — запуск GUI через `python3` в Linux/macOS, с активацией `venv` при наличии.
- `reports/` — генерируемые отчеты; директория исключена из Git.
- `__pycache__/` — кэш Python; директория исключена из Git.
- `api_key.local.txt`, `deepseek_key.local.txt`, `nordrouter_key.local.txt` — локальные файлы ключей, исключенные из Git.

## Запуск и тесты

Установка зависимостей:

```powershell
pip install -r requirements.txt
```

GUI:

```powershell
python app_gui.py
```

или двойным кликом по `start_gui.bat`.

CLI требует переменные окружения `YOUTUBE_API_KEY` и `DEEPSEEK_API_KEY`:

```powershell
set YOUTUBE_API_KEY=your_google_youtube_key
set DEEPSEEK_API_KEY=your_deepseek_key
python agent.py @handle_or_url
```

Тесты (текущий набор — 36 тестов):

```powershell
python test_agent.py
```

Также тесты можно запускать через:

```powershell
python -m unittest -v
```

## Соглашения по стилю

- Используется стандартный Python-стиль с 4 пробелами.
- В коде применяются type hints и `from __future__ import annotations`.
- Имена функций и переменных — `snake_case`, классов — `PascalCase`, констант — `UPPER_SNAKE_CASE`.
- Публичные функции и основные модули имеют docstring.
- Для JSON используется UTF-8 и `ensure_ascii=False`, чтобы сохранять кириллицу.
- Файлы отчетов создаются в `reports/channels/YYYY-MM-DD/`.
- Секреты нельзя выводить в сообщения, коммитить или добавлять в обычные файлы проекта.

## Правила работы

- Перед любой нетривиальной задачей сначала предложи план и дождись моего одобрения.
- Работай маленькими шагами: одна задача за раз, без изменений вне её границ.
- Не меняй архитектуру, структуру папок и зависимости без моего согласия. Если считаешь, что это нужно, объясни почему и жди решения.
- Если задача неясна или противоречит правилам в этом файле, спроси, а не додумывай.
- После каждого завершённого шага перечисли изменённые файлы и кратко объясни, что и зачем изменено.
- В конце каждой задачи или по просьбе владельца обновляй `PLAN.md`.
- В начале новой сессии сначала прочитай `AGENTS.md` и `PLAN.md`, затем кратко перескажи владельцу, на чем остановились, прежде чем что-либо делать.

## Нужно уточнить у владельца

Вопросы, требующие уточнения, отсутствуют. Зафиксированные решения:

- Сейчас используется только DeepSeek.
- Провайдер LLM должен быть вынесен за интерфейс, чтобы Gemini и NordRouter можно было добавить позже без переписывания основной логики.
- Минимальная версия Python — 3.11.
- Основной отчет остается читаемым, JSON добавляется как дополнительный формат.
- Ключи читаются только из переменных окружения или `.env`; `.env` должен быть в `.gitignore`.
- Шифрование ключей не требуется.
- API-ключи нельзя писать в логи.
- Production-готовность включает проходящие тесты, конфигурацию из окружения, таймауты, ретраи и обработку ошибок API, логирование, README с инструкцией запуска и один сквозной прогон на реальных данных.
- Для Cold DM нужна автоматическая rule-based проверка длины, незаполненных плейсхолдеров, шаблонных фраз и наличия персонализации. LLM-оценка пока не используется.

## Фактическое состояние перенесенной версии

- В агент добавлены анализ внешних ссылок, риск-флаги (`referral_farming`, `unverifiable_token_hype`, `leveraged_signals_promotion`), проверка аргументов инструментов, накопление состояния и обязательная проверка наличия предложения услуги в Cold DM.
- `tools.py` дополнительно собирает статистику видео, выбирает репрезентативные комментарии и учитывает внешние ссылки при расчете матрицы монетизации.
- GUI показывает полный отчет и Cold DM на отдельных вкладках, поддерживает копирование сообщения и фильтр каналов по диапазону подписчиков.
- В текущем снимке отсутствует предыдущий `validate_cold_dm` с проверкой длины, плейсхолдеров, шаблонных фраз и персонализации; это отдельная задача на восстановление или пересмотр.
- В текущем снимке также отсутствуют прежние кэширование поиска и явный отказ от ссылок на видео в `parse_channel_input`; поведение нужно отдельно подтвердить тестами и решить, восстанавливать ли его.
- GUI читает ключи из переменных окружения и не сохраняет их на диск; флажок «Запомнить ключи» по умолчанию выключен. `.env` должен оставаться в `.gitignore`.
